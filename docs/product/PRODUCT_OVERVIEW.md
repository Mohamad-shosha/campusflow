# نظرة عامة على منتج CampusFlow (Product Overview)
**منظومة الحرم الجامعي الذكي المتكاملة — جامعة فهد بن سلطان (FBSU Smart Campus OS)**

---

## 1. ما هو منتج CampusFlow؟
**CampusFlow** هو نظام تشغيل جامعي سحابي متكامل (University Smart Campus Operating System) مصمم خصيصاً لتحويل الجامعات إلى مدن جامعية ذكية غير نقدية (Cashless Smart Campuses). 

النظام بيجمع بين أربع ركائز رئيسية في منصة موحدة واحدة بدون الحاجة لاستخدام أنظمة منفصلة:
1. **التنقل والمواقف الذكية (Smart Campus Mobility):** إدارة 30 موقف سيارات عبر 4 قطاعات جامعية، حساسات فوق صوتية (Ultrasonic Sensors) لحظية، محاكاة حركة البوابات الذكية وقراءة اللوحات آلياً (ALPR Gate Scanner)، ونظام تبادل المواقف الذكي (AI Flex-Share).
2. **الخدمات الأكاديمية التشاركية (Collaborative Academic Services):** شبكة دروس التقوية الطلابية (Peer-to-Peer Tutoring)، حجز الساعات المكتبية لأعضاء هيئة التدريس (Faculty Advising)، وغرف الدراسة والبودات التفاعلية (Smart Study Rooms & Pods).
3. **المالية والمحفظة الرقمية (Fintech & Digital Campus Wallet):** محفظة إلكترونية مرتبطة بدفتر أستاذ مزدوج القيد (Double-Entry Accounting Ledger) يمنع التلاعب، سداد الرسوم الدراسية الرسمية مع فواتير ضريبية معتمدة وباركود التحقق الرقمي، وتحويلات فورية بين منسوبي الجامعة.
4. **الحوكمة والإدارة المركزية (Campus Administration & Governance):** لوحة تحكم إدارية مركزية للتحكم في تسعيرات المواقف، وحالات الغرف، وصلاحيات المستخدمين، مع سجل تدقيق أمني غير قابل للتعديل (Immutable Admin Audit Log).

---

## 2. المشكلة التي يحلها المنتج (The Problem Statement)
قبل CampusFlow، كانت الجامعات بتعاني من:
- **أزمة التكدس المروري والتزاحم على المواقف:** الطلاب وأعضاء هيئة التدريس بيقضوا ما بين 15 إلى 25 دقيقة يومياً في البحث عن موقف سيارات، مع تعطيل بوابات الدخول اليدوية.
- **هدر المواقف المحجوزة:** مئات المواقف المخصصة للدكاترة بتفضل فاضية أثناء فراغات الجداول والمحاضرات بدون استغلال.
- **إجراءات السداد الورقية المعقدة:** طوابير في الخزينة المالية لدفع الرسوم أو استخراج إيصالات السداد، مع غياب فوري لتسوية المستحقات المالية.
- **تشتت الخدمات الأكاديمية:** حجز الساعات المكتبية أو البحث عن معيد/زميل للشرح كان بيتم عبر إيميلات عشوائية أو جروبات واتساب غير منظمة وبدون أي ضمانات مالية لجلسات التدريس.
- **غياب الحوكمة المركزية:** صعوبة مراقبة الحرم الجامعي لحظياً ومعرفة معدلات الإشغال والإيرادات وسجلات دخول السيارات.

## 4. الفئات والمستخدمين المستهدفين (Target Personas)
1. **سعود الشمري (طالب هندسة - مقيم):** بيستخدم سيارة يومياً، بيحجز في قطاع الهندسة والحاسب، بيحجز غرف دراسة للمشاريع، وبيشحن محفظته لسداد رسوم الترم.
2. **د. سمير كمال (أستاذ مشارك - كلية الهندسة):** عنده موقف محجوز خاص، بيعرضه في بريك الظهر Flex-Share ليكسب نقاط مالية، وبيحدد مواعيد الساعات المكتبية للطلاب.
3. **فاطمة العنزي (طالبة طب - متفوقة):** بتقدم جلسات تقوية (Peer Tutor) لزملائها في مواد الكيمياء الحيوية، ورصيدها بيتحول أوتوماتيكياً لمحفظتها الجامعية.
4. **عبدالله بن فهد النجار (مسؤول النظام - Campus Admin):** بيراجع سجلات الحركات المالية، بيعدل تسعيرات مواقف ذوي الهمم وشواحن الـ EV، وبيوقف أي حساب مخالف.

## 5. المعمارية التقنية للمنتج (High-Level Architecture)
- **الواجهة الأمامية (Frontend):** مبنية بـ React 18 مع TypeScript Strict، مدعومة بمكتبة مكونات خاصة نقية (Zero-Heavy UI dependencies)، تدعم العربية والإنجليزية (RTL/LTR) والوضع الليلي/النهاري، مع استهلاك كامل لـ REST APIs تحت المسار `/api/v1`.
- **الخلفية (Backend):** مبنية بـ Java 21 و Spring Boot 3.3.4 بنمط Modular Monolith عالي التماسك (High Cohesion, Loose Coupling) مقسم لموديولات استقلالية: `identity`, `wallet`, `parking`, `rooms`, `tutoring`, `officehours`, `notifications`, `admin`, `common`.
- **قاعدة البيانات (Database):** PostgreSQL 15 مدعومة بـ 14 Flyway Migration تؤمن التناسق الصارم (ACID transactions) مع فهارس محسوبة ومحددات قيد (Constraints & Foreign Keys).
- **التشغيل والحاويات (DevOps):** تشغيل كامل عبر Docker Compose بحاويات معزولة ومحمية، واختبارات تكامل مستمرة (CI Pipeline) على GitHub Actions تشمل الفحص المعماري ArchUnit واختبارات Vitest و Maven.
