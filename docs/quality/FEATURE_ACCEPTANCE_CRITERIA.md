# معايير قبول الميزات (Feature Acceptance Criteria) — CampusFlow
**دليل التحقق ومعايير الجودة والـ Definition of Done لكل ميزة في المنظومة**

---

## 1. ميثاق اكتمال الميزة العام (Definition of Done - DoD)
لا تعتبر أي ميزة (Feature) مكتملة في CampusFlow إلا بعد استيفاء الشروط التالية مجتمعة:
1. **سلامة الكود (Code Integrity):** خلو تام من أي أخطاء أو تحذيرات في TypeScript Strict و ESLint و Prettier.
2. **الاختبارات الآلية (Automated Tests):** وجود اختبارات وحدة (Unit Tests) واختبارات تكامل (Integration Tests) تغطي المسارات الإيجابية والسلبية بنسبة نجاح 100%.
3. **الأمان والصلاحيات (RBAC & Security):** تطبيق قيود الصلاحيات المزدوجة (على مستوى الـ API والـ UI) والتأكد من عدم تسريب بيانات غير مصرح بها.
4. **التكامل بين الواجهة والخلفية (Full Integration):** الواجهة تستدعي الـ API الحقيقي مع معالجة حالات التحميل (Loading) والخطأ (Error Toast) دون الاعتماد على بيانات وهمية ثابتة.
5. **البيئة والحاويات (Docker & CI):** نجاح البناء في الـ Dockerfile وسلامة الحاويات في Docker Compose ونجاح الـ CI Pipeline على GitHub Actions.

## 2. معايير القبول التفصيلية لكل ميزة

### F-02: الهوية والمصادقة (Identity & Auth)
- [x] إمكانية تسجيل حساب جديد برقم هوية وطنية أو إقامة سعودية صحيحة وبريد جامعي معتمد.
- [x] تشفير كلمة المرور بخوارزمية BCrypt وتطبيق معايير قوة كلمة المرور (أحرف كبيرة وصغيرة وأرقام ورموز).
- [x] توليد توكن JWT صالح لمدة 15 دقيقة مع Refresh Token في قاعدة البيانات.
- [x] اعتراض أخطاء 401 في المتصفح وتجديد التوكن تلقائياً في الخلفية بدون طرد المستخدم.
- [x] إمكانية تغيير كلمة المرور للمستخدم المسجل وتحديث الاسم ورقم الجوال.

### F-04: المحفظة والدفتر المالي (Campus Wallet)
- [x] منع السحب على المكشوف: لا يمكن بأي شكل أن يقل رصيد المحفظة عن `0.00`.
- [x] تسجيل كل حركة (شحن، تحويل، سداد) كسطر في `ledger_entry` يوضح الرصيد قبل وبعد العملية.
- [x] الحماية من العمليات المتزامنة (Race Conditions) باستخدام `SELECT ... FOR UPDATE` في قاعدة البيانات.
- [x] القدرة على تحويل الرصيد لطالب آخر بمعرفة إيميله الجامعي فورياً.

### F-05: الرسوم الدراسية والفواتير الضريبية (Tuition)
- [x] احتساب ضريبة القيمة المضافة بنسبة 15% وتفصيلها في الفاتورة.
- [x] خصم قيمة الرسوم من رصيد المحفظة وإصدار إيصال سداد فوري.
- [x] توليد كود تحقق رقمي (Verification Hash) مشفر مع باركود QR مطابق لمتطلبات هيئة الزكاة.
- [x] منع سداد الفاتورة المسددة مسبقاً مرتين (Idempotency).

### F-06 & F-07: المواقف الذكية والتصاريح (Smart Parking)
- [x] عرض خريطة حية لـ 30 موقفاً عبر 4 قطاعات توضح الحالة الفعلية لكل موقف.
- [x] رسم سيارات واقعي ثلاثي الأبعاد (Top-Down SVG) بألوان وموديلات مطابقة لبيانات المستخدم.
- [x] إضاءة مصابيح الحساسات السقفية (أخضر=متاح، أحمر=مشغول، كهرماني=محجوز، بنفسجي=دكاترة).
- [x] منع الحجز المزدوج لنفس الموقف في نفس الفترة الزمنية.
- [x] إصدار تصريح رقمي بكود QR مشفر يحمل رقم لوحة السيارة وفترة الحجز.

### F-08: تبادل المواقف الذكي (AI Flex-Share)
- [x] تمكين صاحب الموقف المحجوز فقط من طرحه كعرض Flex-Share.
- [x] تحديد فترة الطرح والحد الأدنى للمكافأة.
- [x] عند مطالبة طالب آخر بالعرض، يتم خصم الرسوم المخفضة منه وإيداع المكافأة فوراً في محفظة صاحب الموقف.

### F-09: بوابة الدخول وقراءة اللوحات (ALPR Gate)
- [x] قراءة أحرف وأرقام اللوحة السعودية ومطابقتها مع الحجوزات النشطة.
- [x] اتخاذ قرار الفتح (`OPEN`) أو الرفض (`DENIED`) خلال أقل من ثانية واحدة.
- [x] توثيق كل حركة في جدول `gate_event_log` مع توقيت البوابة وسبب القرار.

### F-14: لوحة تحكم الإدارة وسجل التدقيق (Admin Governance)
- [x] (Backend): حماية جميع مسارات الإدارة برتبة `CAMPUS_ADMIN` فقط.
- [x] (Backend): تسجيل كل تغيير في جدول `admin_audit_log` دون أي قدرة على التعديل أو الحذف.
- [ ] (Frontend - المهمة الحالية P7-05): بناء شاشات لوحة الإدارة المتجاوبة مع الجداول التفاعلية وأزرار الإجراءات السريعة.
- [ ] (Frontend): اختبارات تفاعل لوحة الإدارة `AdminDashboard.test.tsx` بنسبة نجاح 100%.

### F-15: التحليلات والذكاء التشغيلي (Campus Analytics)
- [ ] بناء مسارات إحصائيات الإشغال والإيرادات (المهمة P7-06).
- [ ] ربط شاشة `AnalyticsView.tsx` بالبيانات الحية القادمة من قاعدة البيانات.
